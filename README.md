# SOHO LMS adapter

Учебный Go-адаптер для чтения SOHO LMS. Версия Go указана в `go.mod`.
Оценки, комментарии, готовность и статусы работ программа не изменяет.

## Запуск

В корне проекта создайте локальный файл настроек:

```sh
cp .env.example .env
chmod 600 .env
```

Заполните `.env` в редакторе своими текущими данными:

```dotenv
SOHO_LOGIN=ваш_логин
SOHO_PASSWORD='ваш_пароль'
```

Затем выполните из корня проекта:

```sh
go run .
```

Команда обращается к реальному SOHO: выполняет вход, проверяет организацию
и читает первую страницу из максимум 30 чатов с фильтрами «Требующие внимания»,
«Только мои», «Сначала старые». Показывает число чатов, статусы и наличие
продолжения. Полный обход пока доступен через `Client.ListHomeworkChats`,
а не через CLI. Метод `Client.GetHomeworkBundle(ctx, chatID, limit)` получает
контекст выбранной работы и сообщения. Он сохраняет исходные данные и
возвращает `Complete=false` с предупреждениями, если контекст недоступен
или история усечена. Подгрузка истории пока не реализована.
Разбор текста, ссылок, встроенных изображений и MultiFile доступен через
`NormalizeHomework`. Файлы скачиваются отдельным `Downloader`.
Работа с живым API пока не подтверждена.

`.env` читается из текущего рабочего каталога и уже исключён из Git.
Переменные окружения имеют приоритет, даже если заданы пустой строкой.
Если раньше экспортировали настройки и хотите использовать файл:

```sh
unset SOHO_LOGIN SOHO_PASSWORD
go run .
```

Формат файла: одна запись `KEY=value` на строку. Пустые строки и строки,
начинающиеся с `#`, пропускаются. Пробелы вокруг ключа и значения удаляются;
парные одинарные или двойные кавычки вокруг значения снимаются, а пробелы
внутри сохраняются. Внутреннее содержимое читается буквально: `$`, `#`, `=`,
обратная косая черта не выполняют подстановок. Комментарии после значения,
`export`, многострочные значения и escape-последовательности не поддерживаются.
Не используйте `source .env`: программа сама читает файл.

## Локальные проверки

Все тесты используют искусственные данные, вход в SOHO не выполняется:

```sh
go test ./...
go vet ./...
go build -o /tmp/soho-adapter .
```

Только тест полного обхода списка, подробно:

```sh
go test ./internal/soho -run '^TestListHomeworkChats$' -count=1 -v
```

Он проверяет несколько страниц, сохранение фильтров и порядка, обновление
повторов, пустую промежуточную страницу, циклы курсоров, предел страниц,
ошибку поздней страницы и отмену контекста. При ошибке частичный список
отбрасывается. Во время обхода очередь может меняться: результат не является
снимком на один момент времени.

В ограниченной среде старые тесты с `httptest.NewServer` могут завершиться
ошибкой открытия TCP-порта. Новые тесты страницы, пагинации и CLI используют
транспорт в памяти. Их можно запустить отдельно:

```sh
go test ./... -run '^(TestInspect|TestParseOptions|TestNormalize|TestDownload|TestClientRejectsRedirect|TestGetHomeworkBundle|TestRun|TestReadEnvFile|TestCredentialsFromEnvFile|TestListHomeworkChats|TestOrganizationIDFromToken)' -count=1
```


## Ручная проверка материалов и скачивания

1. Выполните `go run .`. Возле каждого чата будет ссылка вида
   `https://master.soholms.com/inbox/123`. Это числовой `chat.uid`,
   а не GraphQL ID. Откройте ссылку в своём браузере для сверки.
2. Выберите номер чата из первой страницы и сохраните материалы без скачивания:

   ```sh
   go run . --chat-number 1 --out downloads/review
   ```

   Каталог создаётся с правами 0700, manifest — 0600. Существующий каталог
   с доступом для других пользователей программа отклонит. Manifest содержит
   исходный контекст, сообщения, читаемый текст, ссылки, вложения и предупреждения.
   Откройте напечатанный файл JSON локально в редакторе и сравните текст,
   количество сообщений, вложения и ссылку `Materials.ChatURL` с сайтом.
   `Bundle.Complete` относится к полноте контекста/истории, а не к получению
   внешних страниц или однозначности автора.
3. Очередь может измениться между запусками. Для повторной проверки именно
   того же чата скопируйте **строковый** `Materials.Bundle.ChatID` из manifest.
   Посмотрите напечатанные хосты вложений и разрешите только проверенные:

   ```sh
   go run . --chat-id 'GRAPHQL_ID_ИЗ_MANIFEST' --out downloads/review --allow-file-host 'ХОСТ_ИЗ_ВЫВОДА'
   ```

   Несколько хостов указываются через запятую. Без `--allow-file-host`
   скачивания нет. Не добавляйте в список домены внешних ссылок на задания:
   скачиваются только MultiFile и inline-изображения. Предел одного файла
   по умолчанию 20 МиБ; изменить можно флагом `--max-file-bytes`.
4. Откройте новый manifest: у файлов должны быть `State: downloaded`, локальный
   `Path`, фактические `Bytes` и `MIMEType`. Сопоставьте каждый файл с сообщением
   по `Attachment.MessageID`, исходным именем и `FileID`, если он указан.
   Откройте PDF/изображения локально и сравните с сайтом. Неподдержанный формат
   имеет статус `unsupported`; ошибка — `failed` и причину без URL доступа.
   При частичном скачивании manifest сохраняется, команда завершается с ошибкой.

`--message-limit 50` увеличивает число запрашиваемых сообщений, но не гарантирует
полноту истории. Наличие продолжения явно отражается предупреждением.
Роли «условие»/«решение» автоматически не назначаются; материалы — кандидаты
для ручной проверки. Внешние страницы по `a[href]` не скачиваются.

Скачивание разрешено только по HTTPS с публичных адресов на явно выбранных
хостах. Редиректы запрещены. Проверяются MIME, сигнатура и размер; неподходящий
ответ не публикуется как файл. Имена генерируются, существующие файлы не
перезаписываются. API-токен и cookie на файловый хост не передаются.
Manifest содержит приватные данные и исходные URL доступа: храните его локально,
не добавляйте в Git и не публикуйте. Каталог `downloads/` уже исключён из Git.

Тесты этапов E/F без реального SOHO:

```sh
go test ./... -run '^(TestInspect|TestParseOptions|TestNormalize|TestDownload|TestClientRejectsRedirect)' -count=1 -v
```


При просмотре выбранного чата выводятся имя ученика из `chatPeer.student`,
заголовок чата, время последнего обновления, срок сдачи и даты сообщений.
Заголовок чата не подменяет отдельное название задания, если оно не получено.
Отсутствующие поля показываются как «не указано». Даты выводятся в исходном
формате сервера, без неявного изменения часового пояса.
`History complete: true` означает полноту контекста и истории по ответу сервера;
это не признак успешного скачивания. `not-requested` означает, что файлы
не запрашивались: добавьте `--allow-file-host` с нужными хостами.
