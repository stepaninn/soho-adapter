# SOHO LMS adapter

Go-адаптер и локальный MCP для предварительной проверки домашних работ
нейросетью. Преподаватель проверяет вывод модели и самостоятельно выставляет
оценку, комментарий и результат на сайте. Мутаций работ, статусов и прочтения нет.

## Настройки

Версия Go указана в `go.mod`. В корне проекта:

```sh
cp .env.example .env
chmod 600 .env
```

Заполните логин и пароль в редакторе. Секреты из HAR не используются.
Для обычного скачивания двух уже подтверждённых файловых хостов достаточно
`SOHO_LOGIN` и `SOHO_PASSWORD`. Встроенный список включает
`app-uploads-prod.storage.yandexcloud.net` и файловый хост `selstorage.ru`,
полученный в текущем проекте. `SOHO_RESOURCE_HOSTS` не является требованием API;
это необязательное дополнение списка для других файловых хостов и внешних
заданий. Расширенные настройки:

```dotenv
SOHO_LOGIN=ваш_логин
SOHO_PASSWORD='ваш_пароль'
SOHO_RESOURCE_HOSTS=app-uploads-prod.storage.yandexcloud.net,files.example.org,tasks.example.org
SOHO_OUTPUT_DIR=downloads/mcp
```

Имена `files.example.org` и `tasks.example.org` замените хостами реальных материалов
или удалите. Не используйте wildcard. Добавляйте домен только после проверки,
какой материал с него требуется получить. Одного разрешённого хоста файлов
недостаточно для чтения страницы с другого домена.

Файл читается самой программой без `source`, выполнения команд и подстановок
`$VAR`. Поддерживаются `KEY=value`, кавычки вокруг значения, пустые строки
и комментарии отдельной строкой. Многострочные значения, `export`, escape-
последовательности и комментарии после значения не поддерживаются.
Окружение имеет приоритет, включая явно заданную пустую строку.
Для выбора другого файла есть `--env-file /absolute/path/.env`.

## Авторство: преподаватель и ученик

Любые файлы, изображения, пояснения и ссылки могут присылать обе стороны.
Автор означает отправителя сообщения, а не создателя PDF или внешнего сайта.
У каждого материала сохраняются `Author`, `Role`, `RoleSource`, `MessageID`,
`TimeCreated` и собственный `ID`. Текст и связанные с ним ресурсы остаются
в одном сообщении. Имя автора запрашивается в `userCreated.name`.

Роли определяются автоматически по участникам чата, без заполнения файлов:

- `teachers: participants(roles: [Teacher, HeadTeacher])` — преподаватели
- `students: participants(roles: [Partner])` — ученики в контексте домашней работы
- `userCreated.id` сопоставляется с `participants[].user.id`
- Если профиль отличается, сравниваются явно возвращённые `authUserId` обеих сторон

Нельзя сравнивать `userCreated.uid` с `chatPeer.student.authUserId`: это разные
пространства идентификаторов. Имя, порядок сообщения и расширение файла также
не определяют роль. При противоречивых ролях или недостаточных данных остаётся
`unknown`, а конкретный отправитель и исходные материалы сохраняются.
Сообщение преподавателя может быть заданием, пояснением или обратной связью;
сообщение ученика — вопросом или решением. Это различие анализирует нейросеть
по полному контексту, а не по одной роли автора.

Файлы автоматически сохраняются в подкаталоги `teacher/`, `student/`, `unknown/`.
Ручной `SOHO_AUTHOR_ROLES_FILE` оставлен только как необязательный диагностический
резерв для неподдержанного профиля, когда API не определил роль. Для обычного
запуска эту переменную нужно оставить пустой или не указывать. Данные API имеют
приоритет. Пример резервного формата — `author-roles.example.json`.

## Ручная проверка CLI

```sh
go run .
go run . --chat-number 1 --out downloads/review
```

Список содержит ссылку на каждый чат. Просмотр выбранного чата выводит ученика,
заголовок чата, даты и сводку по сторонам без пошаговых логов. Подробности
доступны с `--verbose`. `--chat-number` выбирает строку из первой страницы
с фильтрами «Требующие внимания», «Только мои», «Сначала старые» и лимитом 30.
Очередь меняется: для повторной проверки того же чата используйте строковый
`Materials.Bundle.ChatID` из manifest, а не номер строки и не числовой UID:

```sh
go run . --chat-id 'GRAPHQL_ID' --out downloads/review --fetch-links
```

Команда скачает PDF/PNG/JPEG с подтверждённых хостов и получит
HTML/текст по исходным внешним ссылкам с разрешённых доменов. Дополнительные хосты можно указать флагом
`--allow-file-host 'host1,host2'` или через `SOHO_RESOURCE_HOSTS`.
Для экспорта без скачивания есть `--metadata-only`.
Без `--fetch-links` ссылки сохраняются в manifest со статусом `not-requested`;
их число входит в сводку неполученных материалов, они не исчезают из результата.

Сверьте с сайтом:

- `Materials.ChatURL`, ученика, сообщения и их время
- `Materials.Messages[].Author/Role`, текст пояснения, ссылки и файлы
- `Downloads[].Attachment` — авторство и исходное сообщение каждого ресурса
- `Downloads[].State/Path/Bytes/MIMEType` — результат получения
- Для HTML: `Downloads[].Text`, `Links`, `Images` и локальную копию `.html.txt`

Откройте скачанные PDF/изображения. Изображения и ссылки, найденные внутри
страницы, сохраняются как новые кандидаты и автоматически рекурсивно не
скачиваются CLI. MCP позволяет прочитать каждый из них отдельно.

Один файл ограничен 20 МиБ; изменить можно через `--max-file-bytes`.
`--message-limit 50` увеличивает выборку сообщений, но не доказывает её полноту.
`History complete` относится к контексту/истории, а не к доступности всех
файлов, ссылок и авторских ролей. Дата сдачи не выводится из даты обновления.
Отдельное название задания не выдумывается из заголовка чата.

## MCP для ChatGPT Desktop

Сервер использует официальный Go SDK MCP и транспорт STDIO. Он сам не вызывает
модель: подключённый ChatGPT использует инструменты и делает предварительную
проверку. Пароль SOHO остаётся в локальных настройках и не является аргументом
инструментов.

```sh
go build -o soho-adapter .
```

В ChatGPT Desktop откройте **Settings → MCP servers → Add server**, выберите
**STDIO** и укажите абсолютный путь к собранному бинарнику. Аргументы:

```text
--mcp --env-file /absolute/path/to/SohoLMS/.env
```

Сохраните и перезапустите подключение. По актуальной официальной инструкции
Desktop поддерживает STDIO: https://learn.chatgpt.com/docs/extend/mcp
Доступность конкретного интерфейса зависит от вашей версии приложения и режима
работы. Для hosted ChatGPT web локальный процесс сам по себе недоступен:
там требуется отдельное подключение через плагин. Сервер не публикуется наружу.

Для клиентов с TOML-конфигурацией пример находится в `mcp-server.example.toml`.
Не записывайте пароль в конфигурацию клиента — сервер прочитает `.env`.
Относительные пути MCP к данным и файлу ролей считаются от каталога `.env`.
STDOUT занят протоколом; даже `--verbose` в MCP не печатает туда диагностику.

Инструменты:

| Инструмент | Результат |
|---|---|
| `list_homeworks` | Одна страница очереди с ID, ссылками, заголовком и учеником; продолжение через `after` |
| `get_homework` | Сообщения с авторами, группы `teacher/student/unknown`, все исходные ресурсы и признаки неполноты |
| `read_material` | Чтение известного ID материала: текст страницы, изображение или PDF вместе с происхождением |

`read_material` не принимает произвольные URL и пути. Сначала вызовите
`get_homework`; ссылки и изображения из полученной страницы также получают ID.
PDF передаётся как бинарный embedded resource, изображение — как image content.
Фактическое чтение PDF конкретной версией ChatGPT нужно проверить: поддержка
транспорта не означает, что клиент умеет интерпретировать любой вид ресурса.

Попросите нейросеть:

> Подготовь предварительную проверку этой работы для преподавателя. Получи
> сообщения и прочитай файлы, пояснения и внешние ссылки обеих сторон. Сохрани
> различие между заданием, ответом и обратной связью; не назначай роли по позиции.
> Укажи найденные ошибки с опорой на ID сообщений/материалов, недостающие данные,
> сомнения и ссылку на чат. Ничего не изменяй в SOHO.

`UnreadMaterialIDs` перечисляет ещё не полученные ресурсы, включая найденные
в прочитанных страницах. `UnresolvedAuthorMessageIDs` показывает содержательные
сообщения без подтверждённой роли. `MaterialsAvailable` остаётся false при
неполной истории, ошибках разбора, неизвестных ролях или неполученных ресурсах.
Это проверка доступности данных, не гарантия правильной проверки математики.
Неоднозначные попытки и неизвестные типы сообщений сохраняются для анализа.

## Ограничения загрузки и приватность

Только HTTPS, явно разрешённые хосты и публичные IP с проверкой до подключения.
API-токен/cookie не отправляются файловым и внешним хостам. Для вложений редиректы запрещены.
Для внешних ссылок допускается до четырёх переходов, каждый только на явно
разрешённый HTTPS-хост с проверкой публичного IP. Referer и секретные заголовки
на переходах удаляются. Для короткой ссылки разрешите также проверенный хост
назначения; неполученная ссылка не считается прочитанной. Страницы с JS, входом или CAPTCHA
не превращаются в гарантированно полученное условие. Пока поддерживается UTF-8.
Проверяются MIME, сигнатура и фактический размер; исходное имя не используется
как путь. Существующие файлы не перезаписываются.

Каталог материалов — 0700, файлы и manifest — 0600. Manifest содержит личные
данные и URL доступа: храните его локально. `.env`, HAR, `downloads/` и бинарник
исключены из Git. Результаты проверки публикует только преподаватель.

## Проверка MCP одной командой

Из корня проекта:

```sh
go run ./cmd/mcp-check
```

Это явная живая проверка: клиент соберёт сервер во временный каталог,
запустит отдельным процессом по STDIO с вашим `.env`, проверит `initialize`,
`tools/list`, очередь, первую работу и до двух файлов. В отчёт выводятся
только количества, роли, MIME и размеры. Тексты работ, имена, пароли и токены
не печатаются. Полученные файлы сохраняются сервером в приватном каталоге
материалов. Для конкретного чата можно передать `--chat-id 'GRAPHQL_ID'`,
для проверки без скачивания — `--max-materials 0`.

Команда не включена в обычные тесты и не изменяет данные в SOHO. Успешная
проверка подтверждает протокол и передачу байтов, но не проверяет внешние ссылки,
подключение вашего Desktop или понимание материалов нейросетью.

## Проверки

```sh
go test ./...
go vet ./...
go build -o /tmp/soho-adapter .
```

В ограниченной среде старые `httptest.NewServer` могут не открыть TCP-порт.
Все новые тесты работают через транспорт в памяти. MCP тестируется настоящими
SDK-клиентом и сервером через `NewInMemoryTransports`, без SOHO и TCP:

```sh
go test ./... -run '^(TestParticipant|TestDefaultDownload|TestMCP|TestAuthorRole|TestMaterial|TestFetchLink|TestReview|TestInspect|TestParseOptions|TestRun|TestNormalize|TestDownload|TestGetHomeworkBundle|TestReadEnvFile|TestCredentialsFromEnvFile|TestListHomeworkChats|TestOrganizationIDFromToken|TestClientRejectsRedirect)' -count=1
go test -race ./internal/mcpserver ./internal/soho -run '^(TestMCP|TestReview)' -count=1
```

Проверки не используют реальные работы, пароли и HAR для входа. Подключение
ChatGPT Desktop и чтение материалов живого SOHO не подтверждаются одними тестами.
