# Проверка HAR: автоматическое авторство

Проверен переданный журнал из 23 записей. Секреты не использовались для входа,
запросы из журнала не воспроизводились. Реальные ID, имена, тексты, URL доступа
и файлы учеников сюда и в тесты не перенесены.

`ChatViewQuery` запрашивает участников с алиасами:

```graphql
teachers: participants(roles: [Teacher, HeadTeacher]) {
  user { id }
}
students: participants(roles: [Partner]) {
  user { id authUserId }
}
```

Объект `participants[].user` и автор `userCreated` имеют ID типа
`UserProfileCommon`. ID самого `ChatParticipant` является отдельным ID.

Сравнение внутри процесса показало:

- Профиль автора текстового сообщения совпал с профилем одного преподавателя
- Профиль автора PDF совпал с профилем участника из `students`
- У автора PDF числовой `uid` отличается от `chatPeer.student.authUserId`
- У события статуса профиль представлен иначе, прямого совпадения ID нет

Это подтверждает прямое сопоставление профилей и опровергает универсальное
сравнение `uid` с `authUserId`. Для другого представления профиля адаптер
запрашивает `authUserId` также у автора и сравнивает только одноимённые поля.
Этот дополнительный вариант покрыт искусственными тестами; новый объединённый
запрос на живом сервере в этой проверке не выполнялся.

В `MultiFile` найден один PDF. Его URL совпал с GET загрузки с HTTP 200.
В журнале также есть мутация прочтения чата, вызванная браузером. Она не
перенесена в адаптер и не выполнялась агентом.
